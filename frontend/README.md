# FILTERME - 로컬 테스트용 크롬 익스텐션

⚠️ 이건 실제 제품이 아니라 **UI/UX 흐름을 로컬에서 눈으로 확인해보기 위한 데모**입니다.
AI 분류 백엔드가 없어서, `content.js`의 `classify()` 함수가 아주 단순한 **키워드 기반 임시 분류기**로
욕설(C02)·정치(C03)·성적 표현(C04)·도배(C05)를 흉내 냅니다. 실제 서비스에서는 이 함수만
AI 분류 API 호출로 교체하면 됩니다.

## VS Code에서 UI만 빠르게 미리보기

매번 크롬에 다시 로드하지 않고 UI만 확인하고 싶다면 `dev/index.html`을 VS Code Live Server로 열어보세요.
자세한 사용법은 [`DEV.md`](./DEV.md)를 참고하세요.

## v0.3.0 — 리팩터링: 설정 화면 중복 제거 + 모달 진입점 1개로 통일

**1) `popup.html` / `content.js` 중복 마크업 제거**

지금까지 `popup.html`(툴바 아이콘용)과 `content.js`의 인페이지 모달이 거의 똑같이 생긴 Settings
화면을 각자 따로 갖고 있어서, 한쪽만 고치면 다른 쪽엔 반영이 안 되는 문제가 있었습니다
(바로 직전에 겪으신 CHZZK 버튼 이슈가 그 예시였습니다).

이제 `content.js`는 설정 화면을 직접 그리지 않고, **`<iframe>`으로 `popup.html`을 그대로 불러와서
재사용**합니다. `manifest.json`에 `web_accessible_resources`로 `popup.html`/`popup.js`/`popup.css`를
노출해서 콘텐츠 스크립트의 iframe에서도 로드할 수 있게 했습니다. iframe으로 열려도
`chrome.storage`는 툴바 팝업으로 열었을 때와 완전히 동일하게 동작합니다 (같은 확장 프로그램의
페이지라 권한이 같습니다). 이제 **설정 화면 마크업은 `popup.html` 파일 하나에만 존재**합니다.

탭마다 내용 길이가 달라서, iframe 높이는 `popup.js`가 `postMessage`로 자기 콘텐츠 높이를
부모(`content.js`)에게 알려주고, `content.js`가 그 값대로 iframe 크기를 맞추는 방식으로
자동 조절됩니다.

**2) 모달을 여는 버튼을 1개로 통일**

기존엔 상단 스트립의 로고, 톱니바퀴, 채팅 하단 플로팅 버튼 3곳에서 모두 같은 모달을 열 수
있었습니다. 이제 **채팅 하단 플로팅 로고 버튼 하나만** 모달을 엽니다.
- 상단 스트립의 로고는 순수 장식(브랜드 표시)으로만 남고 클릭 기능이 없습니다.
- 톱니바퀴 아이콘은 아예 제거했습니다 (기능이 겹쳐서 혼란만 줬습니다).

## v0.2.1 — 중요: Settings 화면이 두 파일에 중복되어 있습니다

`popup.html`(툴바 아이콘용)과 `content.js`의 인페이지 모달(로고/톱니바퀴/FAB용)이 **거의 똑같이 생긴
Settings 탭을 각자 따로 갖고 있습니다.** 겉보기엔 하나의 화면 같지만 실제로는 서로 다른 두 개의
마크업이라, **한쪽만 고치면 다른 쪽엔 반영되지 않습니다.**

- `popup.html`의 클래스명: `tp-sublabel`, `tp-row`, `tp-panel` 등
- `content.js` 모달의 클래스명: `fm-modal-label`, `tp-row`(공용), `fm-modal-panel` 등

이번 버전에서 CHZZK 버튼을 양쪽 다 제거했고, 앞으로 헷갈리지 않도록 두 파일의 Settings 섹션
바로 위에 "이거 고치면 반대쪽도 고쳐야 함" 주석을 남겨뒀습니다. My Chat 탭(블러/차단 선택)과
Filter 탭(카테고리 On/Off)도 마찬가지로 두 파일에 중복돼 있으니, UI 문구나 옵션을 바꿀 때는
`content.js`와 `popup.html` 둘 다 확인해주세요.

**→ v0.3.0에서 이 문제 자체를 구조적으로 없앴습니다 (위 항목 참고).**

## v0.2.0 — 큰 구조 변경: 네이티브 팝업 → 인페이지 모달

- **[변경] 전체 설정 진입 방식**: 지금까지는 콘텐츠 스크립트가 `chrome.action` API에 접근할 수 없다는
  제약 때문에, 채팅 안의 버튼을 누르면 "툴바 아이콘을 눌러주세요"라는 안내(코치팁)만 보여줬습니다.
  이번 버전부터는 **로고(FM) / 톱니바퀴(⚙) / 플로팅 버튼을 누르면 그 자리에서 바로 전체 설정
  모달이 뜹니다.** 원래 디자인(로고 클릭 → 즉시 모달)대로 동작합니다.
- 모달은 My Chat / Filter / Settings 3개 탭 구조를 그대로 유지합니다.
- **브라우저 툴바 아이콘 클릭 시 뜨는 `popup.html`은 그대로 남아있습니다** (보조 진입점). 두 UI 모두
  같은 `chrome.storage.local`을 보고 있어서 어느 쪽에서 바꾸든 실시간으로 서로 동기화됩니다.
- 코치팁/빠른 팝오버 관련 코드는 모두 제거했습니다 (더 이상 필요 없어짐).

## v0.1.2 수정 사항

## v0.1.1 수정 사항

- **[수정] 채팅 입력창이 화면 밖으로 밀리는 문제**: FM 컨트롤 바를 `document.body.prepend`로 문서
  흐름에 끼워 넣었던 게 원인이었습니다. iframe은 고정 높이라 콘텐츠가 하나 늘어나면 넘친 만큼
  아래(입력창)가 화면 밖으로 밀려났습니다. → 이제 FM 스트립을 `position:fixed`로 흐름에서 완전히
  분리하고, 대신 네이티브 채팅 컨테이너에 스트립 높이(34px)만큼 상단 padding을 예약해서 겹치지
  않게 만들었습니다.
- **[보강] 팝업 진단 강화**: `popup.js`에 에러 배너를 추가했습니다. 팝업 안에서 뭔가 잘못되면
  빈 화면 대신 빨간 배너로 에러 메시지가 뜹니다.

## 설치 방법

1. `chrome://extensions` 접속
2. 우측 상단 **개발자 모드** 켜기
3. 이미 로드했던 이전 버전이 있다면 **새로고침(⟳) 버튼**을 눌러 최신 코드로 갱신
   (처음이라면 **압축해제된 확장 프로그램을 로드합니다** → 이 폴더 선택)

## "전체 설정 팝업이 안 뜬다"면 이 순서로 확인해주세요

1. **아이콘을 찾을 수 있는지 확인** — 새로 로드한 확장 프로그램은 툴바에 안 보이고 퍼즐 조각(🧩)
   아이콘 안에 숨어 있는 경우가 많습니다. 퍼즐 아이콘 클릭 → FILTERME 옆의 **압정(📌) 아이콘**을
   눌러 툴바에 고정해두면 확실합니다.
2. 그래도 안 뜨면, **툴바의 FM 아이콘을 우클릭 → "검사"(Inspect popup)** 를 선택해서 개발자 도구를
   열어보세요. 콘솔에 빨간 에러가 있다면 그 메시지를 알려주시면 바로 고쳐드릴 수 있어요.
   (v0.1.1부터는 에러가 나면 팝업 안에 빨간 배너로도 표시됩니다)
3. `chrome://extensions` 에서 FILTERME 카드에 **"오류"라고 적힌 빨간 버튼**이 떠 있는지도 확인해보세요.
   있다면 그 안의 로그도 같이 공유해주시면 좋습니다.

## 테스트 방법

1. 유튜브에서 **현재 방송 중인 라이브 영상**을 아무거나 하나 엽니다 (다시보기 X, 실시간 방송만 채팅이 있습니다)
2. 채팅창 상단에 얇은 보라색 줄(FM 컨트롤 스트립)이 보이면 정상 주입된 것입니다
3. 처음 실행이면 채팅 자리에 **온보딩 화면**(카테고리 선택 + 블러/차단 선택)이 먼저 뜹니다 → "적용하고 채팅 보기" 클릭
4. 실제 채팅에서 욕설·정치 키워드가 포함된 메시지나, 짧은 시간에 3번 이상 반복되는 메시지가 오면
   블러 처리되거나(기본값) 사라지는지 확인해보세요
   - 채팅이 조용한 방송이면 직접 자신의 계정으로 테스트 키워드(`content.js`의 `KEYWORDS` 참고)를 채팅에 쳐보면 됩니다
5. 채팅 우측 하단의 **플로팅 로고 버튼**을 눌러보세요 — 그 자리에서 바로 전체 설정 모달
   (My Chat / Filter / Settings 탭)이 뜹니다. (상단 스트립의 로고는 장식용이라 눌러도 반응하지 않습니다)
6. 모달에서 카테고리를 끄거나 표시 방식(블러/차단)을 바꾸면 채팅에 바로 반영되는지 확인합니다
7. (선택) 브라우저 툴바의 FM 아이콘을 클릭해서 `popup.html`도 같은 값을 보여주는지, 서로 동기화되는지 확인합니다
   (`chrome.storage.onChanged`로 실시간 동기화됩니다)

## 알려진 제약 / 다음 단계

- **유튜브 DOM 구조 의존**: `yt-live-chat-item-list-renderer`, `yt-live-chat-text-message-renderer` 같은
  내부 커스텀 엘리먼트 이름에 의존합니다. 유튜브가 채팅 UI를 업데이트하면 셀렉터가 깨질 수 있습니다
  (PRD AC06: 이럴 때 확장 프로그램 전체가 죽지 않고 그냥 필터만 동작 안 하도록 방어적으로 짜여 있습니다 —
  `findItemsContainer()`가 못 찾으면 계속 재시도만 하고 에러를 던지지 않습니다)
- **슈퍼챗/멤버십 메시지는 필터링하지 않습니다** (`yt-live-chat-text-message-renderer`만 처리)
- **분류기는 진짜가 아닙니다**: 키워드 매칭 + 단순 반복 카운트일 뿐이라 오탐/미탐이 많습니다.
  실제 AI 분류 백엔드가 준비되면 `classify(text)` 함수의 반환값만 그 결과로 바꿔치기하면 됩니다
- **CHZZK 등 다른 플랫폼**은 미구현 (PRD MVP 스코프와 동일하게 YouTube 한 플랫폼만)
